# 生成レポートのUIレビュー

白基調、文字の折返し、一覧のメッセージ表示、閉じる固定バーは改善している。一方、動画の狭幅操作、資料不足の説明、画像・動画への到達しやすさに3件の改善点が残る。いずれもP2（通常の改修で対応する使い勝手の問題）とする。表示や保存結果を破壊するP1相当の問題は、今回確認できた範囲では見つかっていない。

## 確認範囲

- `.lakda/report-ui-preview-ja-final-20260911/`と同`en`版のHTML・保存JSON・receiptを読み、現在のCLIで再verifyした。日本語は7 files／106,747 bytes、英語は7 files／106,708 bytesで双方valid。
- 最終のPC概要、日本語390px／200%の動画、390px／100%の動画、PC動画の画面画像を目視し、rendererとviewer、媒体検査の操作内容を照合した。
- runtime source 2件とviewer testのhashは、前回の最終確認時と一致した。今回は実装を変更せず、全566件や媒体40ケースを再実行していない。
- 今回のブラウザ一覧にレポートは開かれていなかった。ローカルHTMLへの直接操作は前回ブラウザ制御のポリシーで遮断されており、回避経路は使っていない。したがって今回は保存画面と生成物・操作記録によるレビューであり、新たな手動操作の実証ではない。全入力は人工データである。

## UIR-01 / P2: 200%の狭幅では動画の再生・シーク操作が見つけにくい

Edgeの390px・200%（195 CSS px）の`video-player.png`では、動画は表示されるが、通常幅で見える再生ボタンとシークバーが見えず、三点メニューだけが残る。100%とPCの保存画面には両方が見える。表示幅を満たすだけでは、動画を確認する操作の見つけやすさを保証できていない。

既存の`video-controls`検査は`controls=true`、Spaceによる再生、`currentTime`の直接設定による位置移動、非表示・close時の停止を確認する。標準シークバーをポインターで操作する検査は含まれない。このため「40ケースpass」を、全幅での通常操作の完了と解釈しない。

対応案: 狭幅でも再生・一時停止へ到達できる表示を確保し、大きな表示で確認する導線を用意する。通常のボタン操作による再生・停止・シークを受入条件に加える。手動の直接操作は未確認なので、完全な操作不能とは断定しない。

根拠: `.lakda/report-ui-media-final-20260911/msedge-390-2/video-player.png`、同`msedge-390-1`／`chrome-1366-1`、`scripts/report-acceptance/media-video.mjs:19`・`:32`、`src/reporting/renderer.ts:34`。

## UIR-02 / P2: 資料不足の理由と「警告0」の意味が概要で分かりにくい

確認した実際の生成物は`generationStatus=degraded`、`coverage-unavailable`のwarningを1件持つが、主要集計は`counts.warnings=0`。これは実行に記録された警告とレポート生成時の不足を別集計にしているためで、値を単純に足すべきではない。しかしUIは概要に「警告0」、上部に生の`degraded`を表示し、不足理由は末尾の根拠欄へ出す。読み手は「警告がないのに資料不足なのか」「何を確認できないのか」を概要で判断しにくい。

対応案: 生成状態の近くに「資料不足: 探索coverage未取得」のような短い理由を表示する。主要件数のラベルを「実行の警告」とし、元の集計と元メッセージを保持する。

根拠: 日英の`report-data.json`／receipt、`src/reporting/viewer-client.ts:50`・`:211`・`:265`。この指摘は生成物と表示コードから確認したもので、当該サンプルの概要を今回直接操作して確認したものではない。

## UIR-03 / P2: 詳細の画像・動画より前に補助情報が多い

詳細はメッセージの後にID、関連ID、seed、実行資格、revision、日時などのfieldを並べ、その後に履歴（1ページ最大100件）、coverage、最後に画像・動画を配置する。媒体を確認するだけでも長くスクロールする構成で、長文や多数の履歴がある場合ほど影響が大きい。保存された媒体画面には実際に直前のcoverage欄が見える。閉じる操作は改善したが、中心用途である画面証跡への到達はまだ遠い。

対応案: メッセージと主要な実行情報の直後へ画像・動画を置くか、「画像・動画へ」の短い移動導線を設ける。revision／ID等の補助情報は開閉領域へまとめる。履歴の証跡選択、所属、元sequenceとfocus復帰は維持する。

根拠: `src/reporting/viewer-client.ts:92`〜`:139`、`.lakda/report-ui-media-final-20260911/msedge-390-1/video-player.png`。多数履歴での到達距離は描画順からの推論であり、今回距離を実測したものではない。
